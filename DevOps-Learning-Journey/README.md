# DevOps Learning Journey

Daily preparation notes, organised as **module → topic (day) → subtopic**.

## Foundations

Understand how computers, operating systems, programs, and application releases work.

- [Day 1: How computers talk](Foundations/day-01-how-computers-talk/README.md) - bits and bytes, binary, hexadecimal, ASCII and Unicode, clients and servers, HTTP requests and responses.
- [Day 2: OS basics](Foundations/day-02-os-basics/README.md) - kernel, processes and threads, RAM and disk, databases and storage, CPU scheduling, and the filesystem tree.
- [Day 3: How a program runs](Foundations/day-03-how-a-program-runs/README.md) - source code, compilation, linking, machine code, runtime, memory, processes, exit codes, .NET execution, and environment variables.
- [Day 4: Build and release lifecycle](Foundations/day-04-build-and-release-lifecycle/README.md) - application artifacts, dependencies, package managers, versioning, environments, configuration, and CI/CD stages.
- [Day 5: Windows vs. Linux](Foundations/day-05-windows-vs-linux/README.md) - Linux servers, distributions, shell and graphical interfaces, and WSL2 on Windows.

## Linux

Work with the filesystem, permissions, accounts, and processes used on Linux servers.

- [Day 6: Filesystem and navigation](Linux/day-06-filesystem-and-navigation/README.md) - pwd, ls, cd, tree, paths, common Linux directories, and hidden files.
- [Day 7: File operations](Linux/day-07-file-operations/README.md) - Create, copy, move, read, edit, and find files without losing track of what changed.
- [Day 8: Linux permissions](Linux/day-08-linux-permissions/README.md) - Understand who can read, change, enter, or run something, and why permission denied does not mean “use 777”.
- [Day 9: Users and groups](Linux/day-09-users-and-groups/README.md) - Connect accounts, numeric identities, team membership, and administrative policy to everyday access problems.
- [Day 10: Linux processes](Linux/day-10-linux-processes/README.md) - See what is running, understand signals, and control your own terminal jobs without confusing them with managed services.
