# rm: remove a file

**Module:** Linux

**Topic:** File operations

## What is rm?

`rm` removes a file’s directory entry. It normally does not send the file to a desktop recycle bin.

Treat this like discarding a document, rather than putting it in another drawer. Read the filename before agreeing.

## Why does this matter in DevOps?

Remove a temporary build output or an obsolete local package. Cleanup should target known files, rather than broad guesses about what is safe to delete.

## Simple practice

Use Ubuntu or another Linux shell. These examples create clearly named sample files under `~/devops-practice/day07`. `printf ... > filename` creates or replaces only that named sample file.

```bash
mkdir -p ~/devops-practice/day07
cd ~/devops-practice/day07
printf "only a practice file\n" > rm-demo.txt
ls -l rm-demo.txt
rm -i rm-demo.txt
ls -l rm-demo.txt
```

Type `y` only for the sample file you just created. The final error is expected: the pathname has been removed. If you answer `n`, the file remains.

**What you should see:**

```text
rm: remove regular file 'rm-demo.txt'? y
ls: cannot access 'rm-demo.txt': No such file or directory
```

## Real scenario: A large log was deleted, but the server’s free space did not increase.

The application may still have the deleted file open. Check open deleted files with appropriate tools, such as `lsof +L1`, and follow the service’s log-reopen procedure. Deleting more files may not solve that cause.

## Important detail

Deleting or renaming mainly depends on write and execute permission on the containing directory, subject to controls such as the sticky bit. A read-only file can sometimes be deleted by someone with suitable directory access. `rm` is not secure erasure; avoid recursive deletion while learning.

## What to remember

**Check the path, then remove only the file you intended.**
