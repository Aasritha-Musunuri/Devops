# mv: move or rename

**Module:** Linux

**Topic:** File operations

## What is mv?

`mv` changes a file’s location or name. After a successful move, the original pathname no longer contains that file.

Moving a book to another shelf does not make a second book. Renaming the label on its cover also leaves one book.

## Why does this matter in DevOps?

Rename a downloaded artifact or move an application package into a release folder. The destination matters because a service may still point at the old name.

## Simple practice

Use Ubuntu or another Linux shell. These examples create clearly named sample files under `~/devops-practice/day07`. `printf ... > filename` creates or replaces only that named sample file.

```bash
mkdir -p ~/devops-practice/day07/mv-archive
cd ~/devops-practice/day07
printf "release 1\n" > mv-old.txt
mv -i mv-old.txt mv-new.txt
mv -i mv-new.txt mv-archive/
ls mv-archive
```

The first `mv` renames the file. The second moves it into an existing directory. `-i` asks before replacing a destination file; no `-r` is needed for moving directories.

**What you should see:**

```text
mv-new.txt
```

## Real scenario: A service cannot find its configuration after someone renamed it.

Check the service’s expected path and the file’s new location. Update the configuration or restore the intended path after confirming the change. A successful move does not update applications that use the old pathname.

## Important detail

Within one filesystem, a move usually changes directory entries. Across filesystems, it generally needs to copy the data and remove the source after success. That can take longer and is not one atomic rename. Moving a file also does not grant a new user access to it.

## What to remember

**Copy leaves the old name; move replaces the location or name.**
