# cp: copy a file

**Module:** Linux

**Topic:** File operations

## What is cp?

`cp` creates a copy of a file or directory. The original stays where it is.

Think of photocopying a page. You now have two pages, and changing the copy does not change the original.

## Why does this matter in DevOps?

Before changing an application configuration, keep a copy of the previous version. A deployment can also copy a built artifact into a staging folder.

## Simple practice

Use Ubuntu or another Linux shell. These examples create clearly named sample files under `~/devops-practice/day07`. `printf ... > filename` creates or replaces only that named sample file.

```bash
mkdir -p ~/devops-practice/day07
cd ~/devops-practice/day07
printf "port=8080\n" > cp-app.conf
cp -i cp-app.conf cp-app.conf.backup
cat cp-app.conf.backup
```

The first two commands create and enter your practice folder. `printf` creates the sample configuration. `cp -i` copies it and asks before replacing an existing destination. `cat` lets you inspect the copy.

**What you should see:**

```text
port=8080
```

## Real scenario: You copied a configuration folder, but the application still reads the old settings.

Check the full destination path. If a destination directory already exists, `cp -r configs backup` can create `backup/configs`, rather than replacing the contents where you expected. Confirm the application’s configured path before restarting it.

## Important detail

Plain `cp` can overwrite a destination file. To copy a directory, use `cp -r source-folder destination-folder`. For preserving attributes during a backup, GNU `cp -a` is useful, but a copy of a live database is not automatically a consistent database backup.

## What to remember

**Copy means two copies; the source stays.**
