# ps: take a snapshot of processes

**Module:** Linux

**Topic:** Linux processes

## What is ps?

`ps` displays information about processes that exist when you run it. A process ID, or PID, identifies a process within its PID namespace.

It is a photograph of the workers currently present, rather than a live video.

## Why does this matter in DevOps?

Check whether an application process exists, which account owns it, and which parent started it. This is a starting point for investigating restarts or missing processes.

## Simple practice

Use an interactive Bash terminal. Commands that create a timer affect only the sample process you start here.

```bash
sleep 60 &
practice_pid=$!
ps -p "$practice_pid" -o pid,ppid,user,stat,comm
wait "$practice_pid"
```

`&` starts the harmless timer in the background. `$!` captures its PID immediately. `-p` selects it; `-o` chooses columns. PPID means parent PID, while STAT describes process state. Read the next topics for more about jobs and signals.

**What you should see:**

```text
A row describing your sleep process. The last command waits for this short practice task to finish.
```

## Real scenario: A process appears in ps, but customers still get errors.

Process existence only shows that something is running. Check the application’s response, configured port, logs, and dependencies. A waiting or broken application can still have a valid PID.

## Important detail

PIDs can be reused after a process exits. Do not act later on a copied number without verifying it still identifies the intended process. Container and host PID views can differ. A snapshot can also miss a process that starts and exits quickly.

## What to remember

**ps answers “what exists now?”, not “is the application healthy?”**
